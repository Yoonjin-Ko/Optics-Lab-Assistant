# 데이터 분석과 모델 검증

- **물리 현상·수집 오류·계산 오류·표시 문제**를 구분합니다.
- 결과를 보기 전에 비교 기준과 평가 조건을 정합니다.
- 계산 속도 개선과 결과의 타당성은 각각 검증합니다.

## 실험 이론
### 이상치와 시계열
튀는 값은 실제 이벤트·측정 잡음·통신 오류·단위 변경에서 생길 수 있습니다. 원시 데이터, 시간축, 단위, 결측 표시, 장비 변경 이력을 먼저 확인합니다. 그래프 축을 고정하면 비교는 쉬워지지만 원시 값이 고쳐지는 것은 아닙니다.

단순 이동평균:
\[
\bar x_t=\frac1w\sum_{k=0}^{w-1}x_{t-k}.
\]
창을 늘리면 변동이 완화되는 대신 급격한 변화에 늦게 반응합니다. 미래 데이터를 포함한 중심 이동평균은 실시간 판단에서 사용할 수 없는 정보를 포함할 수 있습니다.

### 학습·검증·테스트
학습은 매개변수 추정, 검증은 모델·설정 선택, 테스트는 최종 평가에 사용합니다. 시계열은 시간 순서를 지키며 미래 정보 유입을 막습니다. 스케일러·결측 대체·특징 선택은 학습 구간에서 적합하고 나머지 구간에는 변환만 적용합니다.

**데이터 누출:** 예측 시점에 알 수 없는 정보가 학습·전처리·평가에 들어가는 문제입니다. 같은 장비·같은 실험의 거의 동일한 표본이 양쪽에 나뉘는 경우도 검토해야 합니다.

### 기준 모델과 지표
\[
\mathrm{MAE}=\frac1n\sum_i|y_i-\hat y_i|,\qquad
\mathrm{RMSE}=\sqrt{\frac1n\sum_i(y_i-\hat y_i)^2}.
\]
RMSE는 큰 오차에 더 민감합니다. 평균 오차만으로 드문 큰 실패를 숨기지 말고, 조건별 성능과 큰 오차 사례도 봅니다. 마지막 값 유지·이동평균·물리식 같은 단순 기준과 비교합니다.

### 계산 최적화
NumPy는 배열 연산으로 Python 반복 부담을 줄일 수 있고, Numba는 지원되는 수치 코드를 JIT 컴파일합니다. 어느 쪽이 유리한지는 병목·자료형·메모리 접근에 따라 다릅니다.

**공정한 시간 비교:** 같은 하드웨어·입력·반복 수·출력 정의를 사용하고, JIT 최초 컴파일·입출력 포함 여부를 명시합니다. 여러 번 측정해 산포도 기록합니다. 난수 기반 계산은 동일 수치 일치만 요구하기보다 분포·평균·불확실성의 일관성을 검증합니다.

## 점검 순서
1. 데이터 정의와 단위·시간·출처를 고정합니다.
2. 원시 데이터와 처리 단계를 분리해 보존합니다.
3. 작은 입력·극한값·독립 계산으로 계산식을 검증합니다.
4. 기준 모델과 동일 조건으로 비교합니다.
5. 정확도·불확실성·실행 시간을 함께 기록합니다.
