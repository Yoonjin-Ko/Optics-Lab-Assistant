# 광학 계산 에이전트 개선

## 해결하려는 문제
가상실험은 브라우저에서 계산했지만, 채팅의 수치 답변은 서버가 직접 계산하지 않았습니다. 문서의 단위·공식을 LLM이 해석하는 과정에서 단위 혼동이나 입력 누락이 생길 수 있었습니다.

## 변경한 흐름
질문 분류 → 관련 MCP 문서 조회 → 계산 담당 노드 → 실제 MCP `calculate_optics` 호출 → 계산 결과 작성 → 계산 계약 확인 → 답변.

- **질문 분류:** 지원하는 계산과 설명·점검 질문을 구분합니다. 계산 입력 해석은 제한된 규칙 기반이며 자유 형식의 모든 한국어를 이해하지 않습니다.
- **조사 담당:** 기존 MCP 리소스에서 식과 적용 조건이 있는 문서를 읽습니다.
- **계산 담당:** 수치·단위를 받아 정해진 수식을 실제 MCP 도구에서 실행합니다.
- **작성·검수:** 계산 경로는 도구 결과로 결정론적으로 작성해 수치가 LLM 재생성으로 바뀌지 않게 합니다. 일반 이론·점검 답변은 기존 LLM 작성·형식 검수 경로입니다.

각 담당은 LangGraph 노드이며 모두 독립적인 LLM 에이전트인 것은 아닙니다. 새로운 노드는 `@traceable`로 기록되지만 실제 LangSmith 수집은 사용자의 추적 설정에 따릅니다.

## 지원 계산과 사용 예
| 계산 | 채팅 입력 | 대표 결과 |
|---|---|---|
| 광자 에너지 | 532 nm 광자 에너지 계산 | 약 2.33053 eV |
| XRD | XRD 파장 0.15406 nm 면간격 0.3 nm 각도 계산 | θ≈14.8783°, 2θ≈29.7566° |
| 간섭계 파장 | 마이켈슨 거울을 0.1582 mm 이동 무늬 500개 파장 계산 | 632.8 nm |
| 무늬 주기 수 | 마이켈슨 변위 1 µm 파장 500 nm 무늬 계산 | 4주기 |
| 편광 투과율 | 편광판 45도 투과율 계산 | 50% |
| 얇은 렌즈 | 렌즈 초점거리 10 cm 물체거리 30 cm 상 거리 계산 | 상 거리 15 cm, 횡배율 −0.5 |

해당 가상실험 화면에서는 전송 순간의 입력을 구조화해 첨부합니다. 질문의 명시값을 우선하며, 사용한 값이 질문·가상실험·1차 회절 가정 중 어디서 왔는지 표시합니다. 거울 실험과 망원경·현미경의 다양한 역설계까지 새 도구가 모두 지원하는 것은 아닙니다.

## 검증 범위
- m·cm·mm·µm·nm·Å의 길이 변환, deg·rad 각도 구분.
- 누락·단위 불일치·비유한 숫자·0으로 나누기·물리 조건 확인.
- Bragg 식의 nλ>2d, 렌즈의 u=f 등에서는 가짜 결과를 출력하지 않음.
- 짧은 정의 질문에는 계산 도구를 호출하지 않음.
- 입력이 여러 값으로 모호하면 임의로 선택하지 않고 필요한 값을 다시 요청.

이는 **지원 수식의 입력·수치 계약 검증**입니다. 모델의 모든 물리 가정이나 일반 LLM 답변의 사실성을 검증하는 기능은 아닙니다. XRD 결정 소멸·강도, 실제 렌즈 수차, 장비 교정은 계산하지 않습니다.

## 재현 가능한 평가
```bash
LANGCHAIN_TRACING_V2=false .venv/bin/python -m unittest discover -s tests -v
LANGCHAIN_TRACING_V2=false .venv/bin/python eval/optics_calculation_eval.py
```

평가 결과는 `eval/optics_calculation_results.json`에 질의·기대값·실제값·상태·MCP 호출 수·응답 시간을 저장합니다. fake LLM으로 실행하되 MCP 서버와 계산은 실제 실행합니다. Ollama/OpenAI의 답변 품질·응답 지연을 측정한 것은 아닙니다.

## Before / After와 한계
| 항목 | 변경 전 코드 | 변경 후 |
|---|---|---|
| 수치 계산 위치 | 브라우저, 또는 LLM의 수치 답변 | 지원 채팅 계산을 서버/MCP에서 수행 |
| 입력·단위 확인 | 범용 수치 계약 없음 | 지원식별 단위·도메인 검사 |
| 오류 응답 | 작성 프롬프트에 의존 | 오류 상태·필요 값의 구조화 응답 |
| 계산 출처 | 프론트 계산 조건 첨부 | 실제 호출 도구·식·문서·입력 출처 표시 |

이 표는 코드 구조의 비교입니다. 변경 전 실행 로그를 확보하지 않았으므로 검색 정확도·지연·비용이 몇 % 개선됐다는 주장은 하지 않습니다. 현재 research 노드의 인위적 작업 지연(0.35초)도 측정 응답 시간에 포함됩니다. 규칙 기반 질의 해석은 복잡한 목표·여러 계산을 놓칠 수 있으며, 지원하지 않는 계산은 기존 답변 경로로 진행할 수 있습니다.

## 주요 코드
- `agent/optics_calculations.py`: 단위·수식·질의 입력 해석·결과 작성
- `mcp_server.py`: 실제 계산 도구 노출
- `agent/graph.py`: 계산 노드와 분기·검수 연결
- `web_chat.html`: 전송 시 실험 입력 스냅샷·계산 진행 표시
- `tests/test_calculations.py`: 단위/예외와 실제 MCP 그래프 통합 테스트
